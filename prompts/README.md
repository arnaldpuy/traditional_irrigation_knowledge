# Coding prompts

This folder holds every prompt behind a number reported in the paper. Each
prompt is a plain-text instrument: it sets the coder role, the task, the coding
rules, the controlled vocabulary and worked examples, and the exact JSON output
schema. Prompts are identified in the run manifests by the SHA-256 digest of
their instrument text (the `SYSTEM ROLE` line onward for the analytical prompt;
the whole file for the single-field prompts), so the exact instrument behind
any coded file is recoverable.




## The multi-field instrument

| File | Run by | What it codes |
| --- | --- | --- |
| `analytical_coding_prompt_v1.txt` | `code/02` (Claude + DeepSeek, full 16-field codebook), `code/04` (the function-attribution arms of the UA/SA, three families) | The analytical scheme: epistemic type, functions, sensory channels, physical variables, eroding technologies, and the `efficiency_legible` removal test. This is the paper's engine. |
| `analytical_coding_prompt_v1_attribution_strict.txt` | generated by `code/04` | The same instrument with ONLY the `functions (multi)` header line replaced by a stricter attribution rule; archived verbatim so the arm ships as run. |
| `analytical_coding_prompt_v1_attribution_broad.txt` | generated by `code/04` | As above, broader attribution rule. |

The strict/standard/broad attribution wordings are one of the three factors of
the 1,080-cell function grid (with LLM family and vote rule).

## Single-field instruments

Each re-codes one variable under alternative wordings and model families. All
output a small JSON object, one assumption per request.

| File | Run by | Field and rule |
| --- | --- | --- |
| `efficiency_standard_prompt.txt` | `code/historical/headline`, `code/03` | `efficiency_legible` under the removal-test rule with worked examples. One of the three wordings of the 1,080-cell headline grid. |
| `efficiency_short_prompt.txt` | `code/historical/headline`, `code/03` | Same field, one-sentence wording, no worked examples. Second grid wording. |
| `efficiency_strict_prompt.txt` | `code/historical/headline`, `code/03` | Same field, admits only water and yield quantities. Third grid wording. |
| `severing_strength_prompt.txt` | `code/historical/headline`, `code/historical/headline`, analysed by `code/11` | For each of five modernization technologies, the severity with which it would sever the assumption: `direct` / `indirect` / `potential` / `none`. Feeds the 720-cell severing grid. |

## Models

The full-codebook coding (`code/02`) used Claude `claude-opus-4-8` and DeepSeek
`deepseek-chat` (retired by the provider after that run), five draws each,
majority vote. The UA/SA arms use three families: `claude-opus-4-8` (800 output
tokens), `deepseek-v4-pro` (3,000 tokens — a reasoning model that returns empty
content at 800) and OpenAI `gpt-5.4` (2,500 completion tokens). Models, draw
counts and prompt digests are recorded in the run manifests under
`datasets/output/`.
